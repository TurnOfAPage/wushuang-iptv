# 山东移动「四口盲插」抓源方案

> 适用：山东移动宽带，光猫 **4 个 LAN 口都能上网 + 看电视（盲插）**，现状是
> `光猫一个口 → 傻瓜交换机 → 机顶盒 + 电脑`，电脑能上网、电视能看，但**抓不到包**。
> 配套工具：无双IPTV抓源工具 v2.1.0 · 作者：锤无双 · [B站教程](https://www.bilibili.com/video/BV17SWk6VEPZ/) · QQ群：170621740

## 〇、先读我（30 秒结论）

1. **你现在抓不到，不是软件坏了，是电脑根本没进 IPTV 专网。** 盲插口把「上网」和「IPTV」两套网络混在一根线里，电脑默认只走上网那条；IPTV 的组播走在**独立的组播 VLAN** 里，到不了电脑网卡。
2. **抓包（capture）和验证（verify）要求不一样**，先看清楚再选方案：
   - **抓包**＝被动看机顶盒的流量，拿到组播地址。只要让机顶盒的流量「经过」电脑即可（网桥串联 / 端口镜像）。
   - **验证**＝电脑**自己**加入组播组收流。这要求电脑真正进到 IPTV 专网（拿到 `169.254.x`/`10.x`），否则一律 `bytes=0`。
3. **用路由器可以吗？——看型号。** 普通只会上网的路由器**不行**；把路由器当交换机用**也没用**；只有**带 IPTV 口 / VLAN 绑定 / IGMP Proxy** 的路由器才行，而且门槛不低（详见 [方案三](#方案三用路由器可以吗)）。
4. **最省事的两条路**：电脑有双网口 → [方案一 网桥串联](#方案一电脑双网卡网桥串联抓包首选)；愿意买/有管理型交换机 → [方案二 端口镜像](#方案二管理型交换机端口镜像)。想一劳永逸、有光猫超密 → [方案四](#方案四光猫改桥接绑-vlan进阶需超密)。
5. ⚠ **安全**：抓包结果里的 `stb` 字段含机顶盒账号，**只在本机用，分享前务必脱敏**；转发服务**仅限局域网，禁止映射公网**；改光猫前**先截图记录原配置**。

## 一、为什么你现在抓不到（原理速览）

山东移动的「盲插」不是把两个口简单并联。公开资料（山东移动自己的论文《一种光猫三层组网实现机顶盒组播播放的方法研究》）说明：光猫靠 **DHCP Option 60 加密校验 + 终端 MAC 地址学习**，在内部把机顶盒分流到 IPTV 业务、把电脑分流到上网业务，对外才表现为「任意口都能上网+看电视」。

由此带来四道坎，**任何一道都会让你抓不到**：

| # | 坎 | 说明 |
|---|---|---|
| 1 | **电脑在上网 VLAN** | 电脑拿 `192.168.1.x`、能上网；机顶盒靠 Option60 认证拿 `10.x`。「能上网」恰恰证明电脑没进 IPTV 专网。 |
| 2 | **交换机隔离单播** | 傻瓜交换机按 MAC 转发，机顶盒的认证/点播/心跳是单播，只在「光猫口↔机顶盒口」走，电脑口收不到。交换机≠集线器。 |
| 3 | **组播走独立 VLAN（带 tag）** | 移动 IPTV 的直播组播在**独立的组播 VLAN**，盲插口送出的 IPTV 帧通常带 802.1Q tag。机顶盒认 tag 所以能看；**Windows 网卡默认丢弃带 tag 的帧**，电脑抓不到。 |
| 4 | **网卡硬件过滤** | 就算组播泛洪到电脑口，电脑没加组，网卡硬件直接丢组播帧（见 [使用说明.md](使用说明.md)）。 |

> 社区实测佐证（山东移动 GM219-S 光猫）：把 IPTV 接到普通路由器/单纯桥接后，常常**「能拿到 10.x 的 IP、能点播，就是看不了直播」**，或**「第一天能看、第二天/每 4~5 分钟卡一次」**——根因都是**组播 VLAN 没正确处理 / IGMP 订阅报文没透明转发**。这正好说明：盲插环境下「能看电视」≠「电脑能抓到组播」。

**所以解决思路只有一句话：让 IPTV 的流量真正到达电脑网卡（抓包），或让电脑真正进到 IPTV 专网（验证）。**

## 二、动手前先诊断（别急着改线）

### 2.1 看电脑有线口拿的是什么 IP

Windows 按 `Win+R` → `cmd` → 输入 `ipconfig`，看**有线网卡**的 IPv4：

| 拿到的 IP | 含义 | 对策 |
|---|---|---|
| `192.168.1.x`（能上网） | 在**上网 VLAN**，没进 IPTV | 这就是抓不到的原因，按下面方案改 |
| `169.254.x.x`（无 Internet） | 已进 IPTV 专网（拿不到 DHCP 属正常） | 网络已对，直接抓包/验证 |
| `10.x.x.x` | 已在 IPTV 专网且拿到地址 | 网络已对，直接抓包/验证 |

### 2.2 尽量拿到两个 VLAN ID（关键情报）

移动 IPTV 通常有**两个不同的 VLAN**，别混淆：

- **IPTV 业务 VLAN**：机顶盒拿 IP、点播/认证走的 VLAN。
- **组播 VLAN**：直播组播流走的 VLAN（**看直播必须有它**）。

获取途径（按容易程度）：
1. 问**移动装维师傅**要「IPTV 业务 VLAN 和组播 VLAN」（最直接）。
2. 登录**光猫超级管理界面**（需超密，见方案四），在「网络 → 宽带设置 / IPTV 连接」里看 VLAN ID 和 802.1p。
3. 用本工具先**抓一次包**（方案一/二），从机顶盒 DHCP/IGMP 报文里推断。

> ⚠ **VLAN ID 各地市不同，网上抄来的数字（别省的 431/100/41/48 之类）不能直接用**，必须以你本地实测/装维给的为准。

### 2.3 清点手头硬件（决定走哪条方案）

- 电脑有**几个有线网口**？（板载 + USB/PCIe 网卡可凑双口）
- 有没有/愿不愿买**管理型（带端口镜像）交换机**？
- 路由器**型号**？是否支持 **IPTV 口 / VLAN 绑定 / IGMP Proxy**（OpenWrt、RouterOS、华硕、部分 TP-Link/华为）？
- 有没有**光猫超级密码**？

先跑一句环境总览，看工具建议的组播网卡：

```bat
WushuangIPTV-CLI.exe info
```

| **一 网桥串联** | 电脑双网口 | ★★ | 否 | ✅ 稳 | ⚠ 可能需再处理 | 想最快抓到地址 |
| **二 端口镜像** | 管理型交换机 | ★★ | 否 | ✅ 稳 | ⚠ 可能需再处理 | 有/愿买网管交换机 |

## 方案一：电脑双网卡网桥串联（抓包首选）

**思路**：把电脑串在光猫和机顶盒中间，所有流量必经电脑，pktmon 就能抓全（含开机认证 + 换台加组）。**零额外硬件**（只要电脑有两个有线口），最通用。

### 拓扑

```
光猫盲插口 ──> 电脑网口A
电脑网口B  ──> 机顶盒网口
电脑 WiFi  ──> 家里路由器（电脑自己上网走这条，别动）
```

### 步骤

1. 按上图接线（机顶盒先断电）。
2. Windows：`控制面板 → 网络和共享中心 → 更改适配器设置`，按住 Ctrl 同时选中**网口A 和 网口B** → 右键 → **桥接**。等几秒生成一个「网桥」。
3. 给机顶盒上电，确认它**还能正常看电视**（说明二层透传成功，Option60/VLAN/IGMP 都过去了）。
4. **管理员**运行抓包（见 [第六节](#六抓包验证出列表标准流程)），期间机顶盒开机重启 + 逐个换台。

### 注意

- **关掉 IGMP Snooping**：Windows 网桥默认不做 snooping，IGMP 透明转发，一般没问题。若出现「每 4~5 分钟卡一次」，多半是 IGMP 订阅报文没透传，检查网桥/网卡是否开了 snooping，关掉。
- **VLAN tag 透传**：个别网卡驱动默认「剥离 VLAN tag」，会导致机顶盒异常或抓不到带 tag 的帧。在网卡「高级」属性里关掉类似 `VLAN Strip / 剥离 VLAN` 的选项（不同驱动叫法不同）。
- **电脑上网走 WiFi**：避免电脑自己被卷进 IPTV 的 DHCP。
- 抓包够用；但 `verify` 若 `bytes=0`，见 [方案三/四](#方案三用路由器可以吗) 把电脑接进 IPTV 专网，或直接用机顶盒实播核对。

## 方案二：管理型交换机端口镜像

**思路**：用带**端口镜像（Port Mirror）**的管理型交换机，把「机顶盒口」的流量**复制**一份到「电脑口」。电脑因此能看到机顶盒的单播+组播。

### 拓扑

```
光猫盲插口 ──> 交换机 口1
机顶盒     ──> 交换机 口2   （被镜像口 / 源口）
电脑有线口 ──> 交换机 口3   （镜像目的口 / 观察口）
```

### 步骤

1. 进交换机管理页，找「端口镜像 / Port Mirror / 监控口」。
2. 设**源口＝口2（机顶盒）**，方向选「收发 both / ingress+egress」，**目的口＝口3（电脑）**。
3. 电脑接 口3，**管理员**运行抓包，机顶盒开机换台。

### 注意

- 确认交换机**能镜像带 VLAN tag 的帧**，且电脑网卡能收 tag（同方案一的 VLAN 说明）。
- 这类交换机若默认开 **IGMP Snooping**，组播可能只发给机顶盒口；镜像通常仍能复制，但若抓不到组播，试着**关掉 snooping** 或把组播泛洪打开。
- 同样：抓包稳，`verify` 可能仍需把电脑接进 IPTV 专网。

## 方案三：用路由器可以吗？

**直接回答：分三种情况，只有第三种行。**

### ❌ 情况 A：普通家用路由器（只会 NAT 上网）——不行

把盲插线接路由 WAN、让路由正常拨号/NAT：
- 机顶盒的 **IPoE + Option60 认证 DHCP 过不了 NAT**，机顶盒拿不到 IPTV 的 `10.x` 地址，**电视直接看不了**。
- 路由不认识 IPTV 的组播 VLAN，组播进不来。
- 结论：**不仅抓不到，还会把原来能看的电视搞坏。别这么接。**

### ❌ 情况 B：把路由器当交换机/AP 用（关 DHCP，LAN-LAN 接）——没用

这跟傻瓜交换机完全等价，**解决不了 VLAN 隔离和单播隔离**，电脑照样抓不到。别白费功夫。

### ✅ 情况 C：带 IPTV 口 / VLAN 绑定 / IGMP Proxy 的路由器——可以，但门槛高

支持的路由：**OpenWrt、RouterOS、华硕（梅林）、部分 TP-Link / 华为**（带「IPTV 口 / VLAN / 单线复用 / IGMP Proxy」功能）。这正是工具 [使用说明.md 场景 D](使用说明.md) 的路子，也是社区（恩山、RouterOS 教程）成熟玩法。

**前提情报**（缺一不可，见 [2.2](#22-尽量拿到两个-vlan-id关键情报)）：
- 本地 **IPTV 业务 VLAN ID** 和 **组播 VLAN ID**；
- 机顶盒的 **Option60 / Option12 鉴权信息 + MAC**（很多情况下要让路由「克隆」机顶盒身份，路由自己才能拿到 IPTV 的 IP 并加组）。

**两种典型做法**：

1. **IPTV 口桥接（较简单）**：盲插线接路由 WAN，在路由里把 **IPTV 业务 VLAN 桥接/绑定到某个 LAN 口（IPTV 口）**，机顶盒接该口；**电脑也接该口**（或该口下挂傻瓜交换机）。这样该口就是「独立 IPTV 口」，回到标准搭线，capture/verify 都能跑。
2. **IGMP Proxy 把组播引进整个 LAN（进阶，长期全屋看）**：路由建一个 IPTV 接口（克隆机顶盒 Option60/MAC 拿 `10.x`），开 **IGMP Proxy**，把组播下放到 LAN；再配 **udpxy / msd_lite** 把组播转 HTTP 单播，全家手机/电视直接看。电脑在普通 LAN 口即可抓包/验证。

**必须知道的坑**：
- **「能点播、看不了直播」**：几乎都是**组播 VLAN 没配对**。直播必须有组播 VLAN + 正确的 IGMP。
- **「每 4~5 分钟卡一次 / 第二天不能看」**：IGMP 订阅老化——IGMP 查询/报告没被正确转发。桥接模式下**别乱开 IGMP Snooping**（社区实测：桥接一开 snooping 组播就没了；IGMP Proxy 模式下才可开）。
- 配置复杂度明显高于方案一/二，**普通用户不建议首选**；适合已有合适路由、想长期全屋观看的人。

> 一句话：**路由器「能」，但挑型号、要 VLAN 情报、要克隆鉴权、坑多。这位用户想快速抓源，优先方案一/二；想长期全屋看且有 OpenWrt/华硕等路由，再上方案三。**

## 方案四：光猫改桥接/绑 VLAN（进阶，需超密）

**思路**：在光猫里「造」一个**独立的、untagged 的纯 IPTV 口**，电脑接它，就完全回到工具的标准搭线场景，capture/verify 全通。这是最干净的最终形态。

### 步骤（务必先记录原配置）

1. 拿到**光猫超级管理员密码**（问装维师傅，或网上查该型号默认超密；普通用户背面密码不行）。
2. 登录光猫，**先截图记录**现有上网/IPTV 连接的 VLAN ID、802.1p、绑定端口、模式。
3. 找到 IPTV 连接，**新建/修改一条桥接（Bridge）连接**：
   - 绑定一个空闲 LAN 口（如 LAN2）作为纯 IPTV 口；
   - VLAN 模式选「改写/Tag」，填本地 **IPTV 业务 VLAN ID** 和 802.1p；
   - 在「组播设置」里填**组播 VLAN**，按需启用 IGMP Snooping。
4. 把该 LAN 口设成 **untagged 送出 IPTV**（让普通电脑网卡能收），电脑接这个口。
5. 电脑有线口应拿到 `169.254.x`/`10.x`（无 Internet 正常），WiFi 保持上网。然后标准抓包/验证。

### 风险与注意

- ⚠ **别动上网那条连接**，否则全家断网。改前必备份/截图。
- ⚠ 光猫可能被运营商 **ITMS 远程下发配置改回去**，改了又失效属正常，需重设或联系装维。
- ⚠ 不同型号光猫界面差异大，找不到选项就**问装维**，别乱删连接。
- 没有超密怎么办？社区做法：用**管理型 VLAN 交换机 + 两根线**在光猫外部分离 VLAN（不动光猫），或直接走方案一/二。

WushuangIPTV-CLI.exe refdb carriers --province 山东

## 六、抓包→验证→出列表·标准流程

无论用哪个方案把网络接好，下面流程一致。GUI 点按钮即可，这里给 CLI 版（参数详见 [CLI使用说明.md](CLI使用说明.md)）。

### 6.1 抓包（需管理员终端）

```bat
WushuangIPTV-CLI.exe capture --seconds 90 --out channels.json
```

- 抓包期间：**机顶盒开机重启**（抓开机 DHCP+ 与 IGMP），再用遥控器**逐个换台，每个频道停 3~5 秒**。
- 结果含频道候选 + 流统计 + 机顶盒信息（**含账号，分享前脱敏**）。
- 非管理员运行会返回退出码 `3`。

### 6.2 验证（不需管理员）

```bat
WushuangIPTV-CLI.exe verify --channels channels.json --out verified.json
:: 或一步载入参考库+验证：
WushuangIPTV-CLI.exe verify --province 山东 --carrier 移动 --out verified.json
```

- 组播网卡：搭线阶段选**有线口**（`169.254.x` 也可），可用 `--iface IP` 指定。
- **全部 `bytes=0`** ＝ 电脑没真正进 IPTV 专网（回到第二节诊断 / 方案三、四），或防火墙拦了（见下）。

### 6.3 生成 M3U

```bat
WushuangIPTV-CLI.exe m3u --channels verified.json --outdir D:\iptv
```

得到 `iptv.m3u`（组播直连）+ `iptv-http.m3u`（转发配对版）。

### 6.4（可选）转发 / 推 NAS

```bat
WushuangIPTV-CLI.exe proxy --port 9999 --channels verified.json   :: 前台长驻，放后台任务
WushuangIPTV-CLI.exe push --files D:\iptv\iptv.m3u --method webdav --target http://NAS:5005/iptv
```

> **首次运行若弹 Windows 防火墙，务必点「允许访问」**，否则收不到组播（表现为 verify 全 `ok=false`、`bytes=0`）。转发仅限局域网。

## 七、常见问题排查

| 现象 | 原因 / 处理 |
|---|---|
| 抓包 0 结果 | 是否**管理员**运行？机顶盒是否**开机换台**？电脑是否真能看到机顶盒流量（方案一/二接对没）？交换机是否开了 IGMP Snooping（关掉）？网线插紧？ |
| 电脑有线口是 `192.168.1.x` | 还在上网 VLAN，没进 IPTV → 按方案改接 |
| verify 全 `bytes=0` | 电脑没进 IPTV 专网（最常见）；或**防火墙**点了取消（去「允许应用通过防火墙」改允许）；或组播网卡选错（`--iface`） |
| 能拿 `10.x`、能点播、看不了直播 | **组播 VLAN 没配对**（方案三/四），直播必须有组播 VLAN + IGMP |
| 每 4~5 分钟卡一次 / 第二天不能看 | **IGMP 订阅老化**：IGMP 查询/报告没透传；桥接别乱开 snooping |
| 机顶盒接上网桥/路由后认证失败 | 二层没透传 Option60/VLAN；检查网卡是否剥离 VLAN tag、是否做了 NAT |
| 抓包文件太大 | 默认分析后自动删；要复盘加 `--keep-pcap` |
| 改了光猫又失效 | 被 ITMS 远程改回，重设或联系装维 |

## 八、安全与隐私

- 抓包结果 `stb` 字段含**机顶盒账号**：仅本机使用，**切勿外传或写入公开文件**，分享抓包前脱敏。
- 转发服务（proxy/udpxy）**仅限局域网，禁止映射公网**。
- 改光猫/路由前**先记录原配置**；不确定就问移动装维，别乱删连接。
- 本工具不后台联网、不上传数据；仅 `refdb update` 主动联网下载公开频道列表。
