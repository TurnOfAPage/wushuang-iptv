## 一、平台支持一览

| 平台 | 抓包后端 | 验证/M3U/转发 | GUI | 抓包权限 |

| Windows 10 1809+ / 11 | 系统内置 pktmon | ✅ | tkinter | 管理员 |
| Linux（x64/arm64） | tcpdump（需安装） | ✅ | tkinter（需 python3-tk） | root / sudo |

## 二、快速开始

### 方式一：源码运行（Python 3.10+，核心零第三方依赖）

```bash
# Linux
sudo apt install python3 python3-tk tcpdump     # Debian/Ubuntu；tkinter 仅 GUI 需要
# macOS（python.org 官方 Python 自带 Tk；tcpdump 系统自带）

python3 src/main.py cli info                     # 环境总览
python3 src/main.py cli verify --province 浙江 --carrier 电信 --out verified.json
python3 src/main.py cli m3u --channels verified.json --outdir ./out
python3 src/main.py                              # 图形界面
python3 src/main.py --selftest                   # 自测（48 项，无需网络/root）
python3 src/e2e_posix.py                         # 回环端到端冒烟（无需 IPTV 网络/root）
```

### 方式二：单文件二进制（PyInstaller 构建）

```bash
./WushuangIPTV-CLI info                          # CLI（控制台）
./WushuangIPTV-GUI                               # GUI（Linux）
open WushuangIPTV-GUI.app                        # GUI（macOS）
sudo ./WushuangIPTV-CLI capture --seconds 90     # 抓包需要 sudo
```

构建：`bash src/build_cli.sh` / `bash src/build.sh`（需 `pip install pyinstaller`）。
GitHub Actions（`.github/workflows/build.yml`）自动构建 linux-x64 / macos-x64 / macos-arm64 / windows-x64 产物。
**注意**：PyInstaller 不能跨平台交叉编译，macOS 产物必须在 macOS 上构建（本地或 CI）。

## 三、与 Windows 的差异

### 1. 抓包：pktmon → tcpdump
- Linux 安装：`sudo apt install tcpdump`（Debian/Ubuntu）/ `sudo dnf install tcpdump`（Fedora）。macOS 系统自带。
- 抓包需要 **root/sudo**（Windows 是管理员）。`verify / m3u / refdb / proxy / push` 等其它子命令**不需要**。
- Linux 缺省 `tcpdump -i any`（抓全部网卡）；macOS 无 `any`，缺省选建议的有线口。可用 `--iface 设备名或IP` 指定：
  ```bash
  sudo ./WushuangIPTV-CLI capture --seconds 90 --iface eth0
  ```
- 产物直接是 pcap（无需 etl 转换）；`-i any` 的 LINUX_SLL/SLL2 链路类型分析器已支持。
- `.etl` 文件是 Windows pktmon 专属，Linux/macOS 上请提供 pcap/pcapng。

### 2. 网卡枚举
- Linux：`ip -j addr`（无 iproute2 时回退 ifconfig），无线口按 `/sys/class/net/*/wireless` 识别。
- macOS：`ifconfig` + `networksetup`（Wi-Fi 口识别）+ `route`/`ipconfig getpacket`（网关/DHCP）。
- 选口策略与 Windows 一致：组播验证优先有线口，udpxy 地址优先有网关的口。`info` 的 `suggested_multicast_iface` 可用 `--iface` 覆盖。

### 3. NAS 推送
- Windows：UNC 路径（`\\NAS\共享`）+ `net use`，或映射盘。
- Linux/macOS：
  - **已挂载目录**（推荐）：`--method smb --target /mnt/nas/iptv` 或 `/Volumes/共享/iptv`，直接复制；
  - **smb:// URL**：`--target smb://192.168.1.84/共享/iptv --user 账号 --password 密码`，走系统 `smbclient`（`sudo apt install smbclient` / `brew install samba`）。
- WebDAV 全平台一致。

### 4. GUI
- tkinter 跨平台；字体按系统自动选择（Windows 雅黑 / macOS 苹方 / Linux Noto Sans CJK 等，缺省自动回退）。
- Linux 运行 GUI 需 `python3-tk`；无头服务器上 CLI/selftest 不受影响（tkinter 缺失时 GUI 给出安装提示）。
- macOS 未签名应用首次打开：**右键 → 打开**（或 `xattr -d com.apple.quarantine 文件`）；正式分发建议 Apple Developer 签名 + 公证。
- 高 DPI：Windows 按系统 DPI 自适应（原逻辑）；Linux/macOS 由 Tk 处理。

### 5. 防火墙
- Windows：首次运行点「允许访问」（原说明不变）。
- macOS：若开启应用防火墙，首次收流/监听会弹窗，点「允许」。
- Linux：桌面发行版一般无入站拦截；服务器若启用 iptables/firewalld，放行组播（IGMP + UDP 高端口）与转发端口（默认 9999，仅限局域网）。

### 6. WSL 特别说明
- WSL2 默认 NAT 网络**收不到物理局域网的 IPTV 组播**；真实抓源请用真机 Linux，或 Win11 的 WSL 镜像网络模式（`.wslconfig` 加 `networkingMode=mirrored`）。
- 回环端到端测试（`e2e_posix.py`）与 selftest 在 WSL 里可正常运行，用于开发回归。

## 四、CLI 协议变化（向后兼容）

- `info` 新增字段：`platform`（win32/linux/darwin）、`capture_backend`（pktmon/tcpdump/null）、`capture_backend_path`；原 `pktmon` 字段保留（非 Windows 为 null）。
- `capture` 新增 `--iface`（Linux/macOS 指定抓包网卡）。
- 退出码不变：`0`成功 / `1`失败 / `2`参数错误 / `3`需管理员/root。
- 其余子命令与 JSON 结构完全不变，AI 工具脚本无需修改。

## 五、鸿蒙PC（HarmonyOS NEXT）精简版

- 纯血鸿蒙**不运行 Python / Linux ELF / Windows PE**，原生应用须用 ArkTS/ArkUI 开发。
- **精简版已开发**：仓库 `harmony/` 工程（DevEco Studio 6 / API 22），含参考库载入、
  `MulticastSocket` 组播验证、M3U 生成导出、`TCPSocketServer` HTTP 转发；hvigor 构建通过，
  产物 `entry-default-unsigned.hap`。**测试版：未签名、未真机测试，仅供参考**，详见 [harmony/README.md](../harmony/README.md)。
- 第三方应用**无原始抓包权限** → 鸿蒙版不含抓包发现频道，靠全国参考库 + 实测验证。
- 运行方法：DevEco Studio 打开 `harmony/` → 登录华为账号自动签名 → 模拟器/真机运行。
